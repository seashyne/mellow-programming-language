# MellowLang workspace

## Overview

`docs/PROJECT_STRUCTURE.md` is the authority on where things live. This skill adds
the enforcement rules and the affected-check workflow so changes land in the right
tree and are verified with the narrowest useful gate.

## Directory contract

| Change | Tree |
| --- | --- |
| Syntax, compiler, CLI, compatibility VM, packages, LSP | `src/mellowlang/` |
| Default engine (C compiler + VM) | `native/standalone/` |
| Language contract and syntax locks | `spec/`, `SPEC.md` |
| Built-in library behavior | `stdlib/` |
| Tests, fixtures, native parity | `tests/` |
| Benchmarks and reports | `benchmarks/` |
| Official and curated packages | `starter_packages/`, `mellow_packages/`, `frameworks/` |
| Integrations | `sdk/`, `plugin_sdk/`, `vscode-extension/` |
| Hosted services | `apps/deploy/` |
| Release packaging | `packaging/` |
| Docs and examples | `docs/`, `examples/` |

Never add implementation code at the repository root; only `main.py` and `setup.py`
are permitted wrappers there.

## Hard rules (tests/test_workspace_boundaries.py)

- No tracked `native/standalone/**/*.{c,h,inc}` file may mention `mellowlang`. The
  standalone runtime is C-only; the Python layer is a separate product surface.
- Repository root holds no `.py/.c/.h/.js/.ts` files beyond `main.py`, `setup.py`.
- `.mellow` and `.mel` sources live only under `benchmarks`, `examples`,
  `frameworks`, `mellow_packages`, `native`, `project_template`,
  `starter_packages`, `stdlib`, `tests`.
- `mellow_packages/registry/**/installed/` stays uncommitted; install output is
  regenerated by tests.
- Every tracked top-level directory appears in `docs/PROJECT_STRUCTURE.md` as a
  backticked path. Update that document in the same change as any move.

Generated and vendored trees are gitignored, not tracked: `tools/` (benchmark
toolchains such as `tools/zig`), `mellow_packages/installed/`, `.tmp*/` scratch
dirs, `build/`, `.wrangler/`. If a change makes
`scripts/verify-changed.ps1 -ListOnly -ByRoot` report tens of thousands of files,
fix the ignore rule before continuing.

## Affected-check workflow

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -ListOnly -ByRoot   # what would run
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1                     # run those jobs
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -Base main          # branch diff
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -Only workspace,nativePy
```

Jobs: `workspace` (boundary gate), `native` (CTest), `nativePy` (`tests/native`),
`python` (`tests/core` + quality gates), `language`, `packages`, `benchmark`.
`native` runs CTest against whatever is already in `build/standalone-release`;
after touching `native/**` build first with
`cmake --build build/standalone-release --config Release`, otherwise the job
passes against a stale binary and proves nothing.
Docs-only edits map to no jobs; `.github/`, `scripts/`, `pyproject.toml`, and
`setup.py` map to all jobs. Run `workspace` plus the touched jobs before
reporting work complete; do not run the benchmark job unless
`benchmarks/` or the runtime hot paths changed. The benchmark harness reads its
standalone workload from `benchmarks/fixtures/hello.mellow`, never from
`examples/`, because `examples/` is user-facing sample code that gets rewritten.
The script exits 1 and lists the
failed jobs, so compare its failures against the pre-existing set before
attributing them to a change.

## Splitting long files

`tests/language/test_source_structure.py` holds `LINE_CEILINGS`: any file over
1,000 lines must be declared there, and a declared file may never exceed its
ceiling. Lower a ceiling when a file shrinks and delete the entry once it drops
under the limit. Raise a ceiling only by splitting the file instead.

Established seams, in the tree that owns them:

- `src/mellowlang/host/` - `base.py` for `HostRegistry`/`HostFunction`/allowlist,
  `families/<name>.py` for each `register_<name>_functions(h)` group, `runtime.py`
  as a thin assembler that keeps the original registration order, and
  `families/support.py` for predicates shared by more than one family.
- `native/standalone/src/mellowc.c` - statement dispatch stays; loop-shape
  recognizers move to `mellowc_fastloops.inc` (included, not compiled, so CMake
  needs no change and the helpers stay private to that translation unit).
- `native/mellowvm/src/mellowvm_module.c` - dispatch stays; syscalls, exec, and
  storage live in their `.inc` fragments.
- `src/mellowlang/package_manager.py` - facade over `packages/*`.
- `src/mellowlang/ai_core.py` - facade over `ai/`: `state.py` owns every mutable
  store, one module per concern, and only `registration.py` builds `HostFunction`.
- `src/mellowlang/compiler/optimizer.py` - facade over `compiler/optimizations/`:
  `ir_data.py` owns the shared IR value types, one mixin per pass section, and the
  driver keeps only the op-set constants plus `optimize()`. A stateless giant class
  splits this way without touching a single method body.
- `src/mellowlang/parser.py` - facade over `parsing/`: `errors.py`, `line_text.py`
  (line helpers), `expression_atoms.py` + `expression_postfix.py` assembled by
  `expressions.py` into `ExprParser`, and `block_core.py` (driver state, `BLOCK_RUNS`,
  `parse()`, `sub_block()`) plus one `_run_*` mixin per statement group in
  `stmt_*.py`, assembled by `blocks.py`. Cut a long `if`/`elif` chain at whole
  statement boundaries, keep the chain's order as a tuple of method names, and pass
  the possibly-rewritten `line` from run to run so an alias rewritten by an earlier
  run still reaches the later ones. Nested blocks recurse through `type(self)`, so
  they keep the whole mixin set without importing the assembly.
- `src/mellowlang/vm/python_vm.py` - facade over `vm/interp/`: the giant `if op ==
  ...` chain inside `run()` became the `OP_HANDLERS` table (opcode to family) plus
  one `_exec_*(op, instr)` mixin per family, the builtin-name walk became the
  `STORAGE_GROUPS` tuple over `call_save.py` / `call_net.py` / `call_fs.py`, and all
  instance state stays in `frame.py` so a family holds no state of its own. Two
  traps: `STORAGE_GROUPS` is read as a module global at call time, so patching it on
  a subclass is inert and a non-vacuity check must patch the module; and a relative
  import written inside a moved method body needs one more dot (`from ..x` to
  `from ...x`) - several of those lazy imports sit in a `try/except`, so a miss
  switches a feature off silently. Assert every relative import resolves with
  `importlib.util.find_spec` from its new depth.
- `src/mellowlang/cli/commands/agents.py` - facade over `cli/commands/agent_groups/`:
  `deps.py` keeps the lazy `_lazy_attr` alias block (the handlers were written against
  it, so it stays one assignment per name and no function body), `support.py` the
  helpers more than one group needs, and one module per subject of `mellow agent ...`.
  The layering is one-way - a group imports `deps` and `support`, never a sibling -
  which is what lets a command group move without a second group noticing.
- `src/mellowlang/agents/scheduler.py` - facade over `agents/scheduling/`: `paths.py`
  owns `SCHEDULER_HOME`, the state-file paths and the time/JSON primitives, `state.py`
  the paired `_load_*`/`_save_*` readers, `cron.py` and `backoff.py` stay pure, then
  one module per subject (`jobs`, `webhooks`, `queue`, `drain`, `runner`, `http_api`).
  Ranks make the direction checkable: an import may only point at a lower rank, so a
  subject cannot reach into the driver that calls it and the package stays cycle-free.
- `src/mellowlang/standalone_image.py` - facade over `mvi/`: the byte format
  (`ops.py`, `format.py`, `binary.py`, `consts.py`), the pass (`state.py` owns the
  accumulators, then `scopes.py`, `emit.py`, `entries.py`, `lowering.py`) and the
  surface (`compile.py`), cut out of one 391-line function along its own comment
  seams. Cutting a giant function at its seams means renaming every enclosing local it
  shares to `state.<same name>`, and the rename set is scope-resolved, not the free
  names: a name the block *assigns* counts as well as one it reads, or the extracted
  function silently gets a fresh local and the write is lost (`_pending_syscall_name`
  was read in one block and assigned in another). Rename NAME tokens, not text, so
  comments and string literals keep their prose. `from __future__ import annotations`
  makes a dataclass field and signature annotation dead at runtime, so a borrowed-name
  audit has to split runtime from annotation-only imports and stub each runtime name
  in the module that drew it.

A battery that drives an HTTP handler and a clock adds traps the stateful-machine
check does not hit:

- Python 3.14 compiles a class body's `__firstlineno__` as a *real constant*, so
  moving a nested class changes that const, the mnemonic that loads it
  (`LOAD_CONST` vs `LOAD_SMALL_INT`), the code width, every offset after it, and even
  the number of consts. Compare disassembly with jumps and the exception table mapped
  to labelled-block ordinals, fold both const opcodes together, and compare consts as
  a multiset with the def's own line replaced by a marker.
- Purge `__pycache__` of the package and its new subpackage before importing: a split
  file and its stale `.pyc` can share mtime and size, and then every line number the
  comparison prints is a lie that only flakes.
- Replace `ThreadingHTTPServer` in the owning module with a stub that captures the
  nested `Handler`, then drive requests through `handler.__new__(handler)` with
  `path`, `command`, `headers`, `requestline` and a `BytesIO` `rfile`/`wfile`.
  `BaseHTTPRequestHandler.date_time_string()` reads the real clock, so pin it - and
  `version_string`, `log_message` - or the two sides differ by one second.
- `datetime` is imported per module, so freeze it per module (a `datetime` subclass
  whose `now()` returns a fixed instant) rather than patching the stdlib, which would
  freeze the oracle's own timing too. On-disk JSON then matches byte for byte instead
  of matching only after scrubbing.
- Derive ids from what earlier cases wrote on disk. An invented id returns "not
  found" on both sides and agrees for a reason unrelated to the split.
- A `sort` flag that cannot parse its outcome must fail loudly: the outcome is a
  Python repr, so `json.loads` raises, a silent fallthrough leaves the list in
  scheduler order, and the thread cases stop testing anything. Use `ast.literal_eval`.
  Pin thread-backed cases to `workers=1`, keep one deliberate multi-worker case whose
  items all succeed, and compare `.jsonl` as sorted lines.
- Build case inputs through a factory called per side. An object created once in the
  case list is consumed by the first side, and the second side then sees an exhausted
  stream.
- Scratch oracles are one flat module scope: a non-vacuity loop that restores a
  binding with `real = module.__dict__[name]` silently rebinds the script's own
  `real(text, mapping)` scrubbing helper. Name restore targets distinctly.

Command handlers add oracle traps that a stateful machine does not have:

- Stub-based non-vacuity must be computed per module: a stub only bites where the
  global lives, so a borrowed binding unreachable from its own group's defs reads
  as "stubbing it changed nothing" unless the reachability closure is walked inside
  each module separately.
- Names read only in a nested callback body (the playground/serve `Handler.do_POST`)
  cannot be reached by a synchronous call. Classify them as callback-only through a
  shallow free-name scan instead of failing the sweep.
- Blocking syscalls sink the battery: patch `socketserver.TCPServer.serve_forever`
  to a no-op and bind port 0, and apply the identical patch on both sides.
- Module globals frozen at import time ignore a per-case `HOME` redirect. The agent
  secret store is `Path.home()`-derived, so re-point
  `mellowlang.agents.secrets.SECRET_FILE` at the run's temp home before each case,
  or the battery reads and writes the developer's own store.
- A case whose result is a `TypeError` about arguments is vacuous: it compares two
  identically wrong calls. Fail loudly on that shape.
- Beyond ids, timings, hashes and addresses, `parallel` step lists come back in
  scheduler order. Mask per-run values before sorting the list pieces, so the sort
  key never depends on a value that differs per run.

A split must be verbatim and proven, not reviewed: snapshot the registry or
output before and after, diff handler metadata plus behavior over a call battery,
and rebuild before claiming native coverage.

When a step is not verbatim - a chain becomes mixin methods, `continue` becomes
`return line, i` - code fingerprints no longer apply, so prove behavioural
identity instead: a recursive dataclass fingerprint (including attributes the
driver `setattr`s onto nodes), identical raised-error attributes, the parsed
corpus in `examples/ stdlib/ tests/ mellow_packages/`, and the end-to-end
compiled bytecode. Then show the comparison bites: drop each run from the order
tuple and require the battery to change, because run predicates are near-disjoint
and a plain reorder proves nothing.

Prove a Python split by loading the `HEAD` copy of the module as a probe
(`git show HEAD:<path>` plus `exec(compile(...))` with `__package__` set and the
module registered in `sys.modules`, which `@dataclass` needs to resolve string
annotations), then diff both sides. Two fingerprint traps:

- CPython picks between two identical method loads - `LOAD_ATTR m + NULL|self`
  when the receiver is a module-level assignment, `LOAD_ATTR m` plus a bare
  `PUSH_NULL` when it arrives through a relative package import. Canonicalise both
  to one token or a verbatim move looks like a regression; `co_stacksize` shifts by
  one with it.
- `frozenset` literals print in iteration order, and a `__pycache__` copy keeps the
  order the writing process had. Compare containers as sorted sets and mask object
  addresses and timestamps, or the diff reports noise.

For a stateful machine such as the bytecode interpreter, stdout and the return
value are not enough - compare the whole VM: capture the instance attributes
(`pc`, `stack`, `variables`, the call/frame/try stacks, `budget`, `opcounts`) after
each run, give each side its own temp sandbox and scrub the sandbox name out of the
text, and reset process-wide singletons (`net_core._WS_MANAGER` hands out
connection ids that count up) or the second run differs for a reason that has
nothing to do with the split. Cover the dispatch table by hand-assembling bytecode:
the compiler cannot reach every opcode (13 of 48 in the Python VM), so a source-only
battery leaves families unexercised while still reporting green.

## Moving trees

Use `git mv` and, in the same change, update every path reference: `.gitignore`,
`docs/`, `pyproject.toml`, `package.json`, CI workflows, and test fixtures. Then
confirm the moved path still resolves by running the affected jobs. Move a tree
only when it is clean; leave any tree carrying uncommitted work in place and
report that it is blocked rather than relocating it.

## Writing Mellow for the standalone C compiler

The native parser is line-oriented: `lex_next` treats a newline as end of file.

- Keep each call, list, and map literal on one line, or assign elements to
  variables first.
- `use <module>` requires an alias: `use ledger as ledger`.
- Indexing applies to names, not to call results: write `let r = f(x)` then
  `r["k"]`, not `f(x)["k"]`.
- Only registered native module functions resolve after `get`/`call`; unknown
  names are a compile error, not a runtime lookup.

Ledger, money, time, text, data, and server builtins are native C. Ledger entry
hashes are compared against `mellowlang.ledger_core` in
`tests/native/test_full_native_c_cli.py` and `tests/fixtures/ledger_core.mellow`;
change both sides together or the parity gate fails.
