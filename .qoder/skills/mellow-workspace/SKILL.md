# MellowLang workspace

## Overview

`docs/PROJECT_STRUCTURE.md` is the authority on where things live. This skill adds
the enforcement rules and the affected-check workflow so changes land in the right
tree and are verified with the narrowest useful gate.

## Directory contract

| Change | Tree |
| --- | --- |
| Syntax, compiler, CLI, compatibility VM, packages, LSP | `src/mellowlang/` |
| Default engine (C compiler + VM) | `native/standalone/` |
| Language contract and syntax locks | `spec/`, `SPEC.md` |
| Built-in library behavior | `stdlib/` |
| Tests, fixtures, native parity | `tests/` |
| Benchmarks and reports | `benchmarks/` |
| Official and curated packages | `starter_packages/`, `mellow_packages/`, `frameworks/` |
| Integrations | `sdk/`, `plugin_sdk/`, `vscode-extension/` |
| Hosted services | `apps/deploy/` |
| Release packaging | `packaging/` |
| Docs and examples | `docs/`, `examples/` |

Never add implementation code at the repository root; only `main.py` and `setup.py`
are permitted wrappers there.

## Hard rules (tests/test_workspace_boundaries.py)

- No tracked `native/standalone/**/*.{c,h,inc}` file may mention `mellowlang`. The
  standalone runtime is C-only; the Python layer is a separate product surface.
- Repository root holds no `.py/.c/.h/.js/.ts` files beyond `main.py`, `setup.py`.
- `.mellow` and `.mel` sources live only under `benchmarks`, `examples`,
  `frameworks`, `mellow_packages`, `native`, `project_template`,
  `starter_packages`, `stdlib`, `tests`.
- `mellow_packages/registry/**/installed/` stays uncommitted; install output is
  regenerated by tests.
- Every tracked top-level directory appears in `docs/PROJECT_STRUCTURE.md` as a
  backticked path. Update that document in the same change as any move.

Generated and vendored trees are gitignored, not tracked: `tools/` (benchmark
toolchains such as `tools/zig`), `mellow_packages/installed/`, `.tmp*/` scratch
dirs, `build/`, `.wrangler/`. If a change makes
`scripts/verify-changed.ps1 -ListOnly -ByRoot` report tens of thousands of files,
fix the ignore rule before continuing.

## Affected-check workflow

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -ListOnly -ByRoot   # what would run
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1                     # run those jobs
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -Base main          # branch diff
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-changed.ps1 -Only workspace,nativePy
```

Jobs: `workspace` (boundary gate), `native` (CTest), `nativePy` (`tests/native`),
`python` (`tests/core` + quality gates), `language`, `packages`, `benchmark`.
`native` runs CTest against whatever is already in `build/standalone-release`;
after touching `native/**` build first with
`cmake --build build/standalone-release --config Release`, otherwise the job
passes against a stale binary and proves nothing.
Docs-only edits map to no jobs; `.github/`, `scripts/`, `pyproject.toml`, and
`setup.py` map to all jobs. Run `workspace` plus the touched jobs before
reporting work complete; do not run the benchmark job unless
`benchmarks/` or the runtime hot paths changed. The benchmark harness reads its
standalone workload from `benchmarks/fixtures/hello.mellow`, never from
`examples/`, because `examples/` is user-facing sample code that gets rewritten.
The script exits 1 and lists the
failed jobs, so compare its failures against the pre-existing set before
attributing them to a change.

## Splitting long files

`tests/language/test_source_structure.py` holds `LINE_CEILINGS`: any file over
1,000 lines must be declared there, and a declared file may never exceed its
ceiling. Lower a ceiling when a file shrinks and delete the entry once it drops
under the limit. Raise a ceiling only by splitting the file instead.

Established seams, in the tree that owns them:

- `src/mellowlang/host/` - `base.py` for `HostRegistry`/`HostFunction`/allowlist,
  `families/<name>.py` for each `register_<name>_functions(h)` group, `runtime.py`
  as a thin assembler that keeps the original registration order, and
  `families/support.py` for predicates shared by more than one family.
- `native/standalone/src/mellowc.c` - statement dispatch stays; loop-shape
  recognizers move to `mellowc_fastloops.inc` (included, not compiled, so CMake
  needs no change and the helpers stay private to that translation unit).
- `native/mellowvm/src/mellowvm_module.c` - dispatch stays; syscalls, exec, and
  storage live in their `.inc` fragments.
- `src/mellowlang/package_manager.py` - facade over `packages/*`.

A split must be verbatim and proven, not reviewed: snapshot the registry or
output before and after, diff handler metadata plus behavior over a call battery,
and rebuild before claiming native coverage.

## Moving trees

Use `git mv` and, in the same change, update every path reference: `.gitignore`,
`docs/`, `pyproject.toml`, `package.json`, CI workflows, and test fixtures. Then
confirm the moved path still resolves by running the affected jobs. Move a tree
only when it is clean; leave any tree carrying uncommitted work in place and
report that it is blocked rather than relocating it.

## Writing Mellow for the standalone C compiler

The native parser is line-oriented: `lex_next` treats a newline as end of file.

- Keep each call, list, and map literal on one line, or assign elements to
  variables first.
- `use <module>` requires an alias: `use ledger as ledger`.
- Indexing applies to names, not to call results: write `let r = f(x)` then
  `r["k"]`, not `f(x)["k"]`.
- Only registered native module functions resolve after `get`/`call`; unknown
  names are a compile error, not a runtime lookup.

Ledger, money, time, text, data, and server builtins are native C. Ledger entry
hashes are compared against `mellowlang.ledger_core` in
`tests/native/test_full_native_c_cli.py` and `tests/fixtures/ledger_core.mellow`;
change both sides together or the parity gate fails.
